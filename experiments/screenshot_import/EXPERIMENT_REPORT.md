# 截图课表识别实验报告

## 当前结论

原标准网格方案已经降级为回归基线，不再作为通用架构。真实样本验证表明，完整网格和浅色课程块不能作为进入 OCR 的前置条件：黑白教务表、长截图和弱边框课表会在 OCR 之前失败。

当前 Draft PR 已改为 OCR-first：

1. 对整张图片执行本地 OCR，保留文字与坐标；
2. 识别星期表头与节次标签，限定主课表区域；
3. 从课程文字中的星期、节次和教学周表达建立课程锚点；
4. 根据空间邻域组合课程名、教师、地点和时间；
5. 网格、背景色和课程块仅作为辅助或回退；
6. 生成 ImportDraft V2，并交给 Rust 结构校验和人工复核。

## 已保留能力

- Windows CPU 本地 PaddleOCR；
- 图片预处理与坐标转换；
- OCR token、置信度和调试输出；
- ImportDraft V2 映射；
- Rust 结构校验；
- review / missing / confirmed 证据状态；
- 旧 block / full 合成样本与 benchmark 回归。

## 本轮新增

- `ocr_first.py`：通用文字锚点和空间分组；
- `ocr_first_fields.py`：组合时间文本和完整地点覆盖；
- `ocr_first_pipeline.py`：新的默认主流程；
- `ocr_first_output.py`：OCR-first 调试输出；
- `OCR_FIRST_ARCHITECTURE.md`：架构与验收原则；
- 新测试覆盖彩色卡片表达、黑白表格表达和底部附表排除；
- CLI 默认模式改为 `ocr-first`。

## 本机真实样本核对

两张真实截图仅在本机运行并由人工对照原图核对：

- 彩色课表：识别 14 门课程；课程空间分组和结构时间通过核对，先前由节次解析造成的保守冲突提示已消除。
- 黑白教务长截图：识别 17 门课程；上方主课表范围和全部课程框通过核对，底部附表未被纳入。相同节次的课程由周次或单双周区分，保留的冲突提示属于 `review` 状态下的保守提醒。

这不是跨学校准确率基准。黑白样本中的部分周次、单双周、课程名和教师字段仍需人工复核；Rust 校验只证明结构合法，不代表字段内容已经与原图逐项一致。

## 能力边界

- 不宣称支持所有学校、所有截图版式或免审保存。
- 不接入正式图片选择器、设置页、复核 UI、sidecar 或安装包；这些内容应由后续独立 PR 处理。

真实截图、课程名、教师、地点和本地真值不得提交仓库或 CI Artifact。Rust 校验只证明结构合法，不代表字段内容正确。
