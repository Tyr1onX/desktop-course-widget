# OCR-first 课表截图识别

## 为什么重构

旧实验把“完整网格”和“浅色课程块”当成 OCR 前置条件，因此彩色标准课表可用，但黑白教务表、长截图、弱边框或无色块课表会在 OCR 之前失败。它可以作为窄范围实验，却不能成为通用截图导入架构。

## 新主流程

```text
整图本地 OCR
→ 保留文字、坐标和置信度
→ 定位同一行的星期表头与左侧节次标签
→ 限定主课表区域，排除顶部信息和底部附表
→ 从课程文字中的星期、节次、教学周表达建立锚点
→ 按星期列和垂直邻域聚合课程名、教师、地点与时间
→ 缺少显式时间时，才使用网格坐标辅助
→ 生成 ImportDraft V2 并进入人工复核
```

## 证据优先级

1. 课程文字中明确出现的星期、节次和教学周；
2. OCR 文字框相对星期表头、节次标签的位置；
3. 可用网格线和课程块；
4. 无法唯一确定时进入 `review`，不得整体失败或静默猜测。

## 兼容策略

- `ocr-first` 是 CLI 默认模式。
- 旧 `block` / `full` 管道继续保留，专门用于标准网格回归和历史 benchmark。
- OCR-first 没有形成课程记录、但旧结构检测可靠时，可作为回退证据使用。
- 不为彩色卡片、黑白表格或具体学校建立独立模板分支。

## 隐私与验收

真实课表截图只在用户本机测试，不提交 Git 或 CI Artifact。自动评分必须使用来源明确、带稳定课程身份键的真值；Rust 校验只证明数据结构合法，不能代替人工核对字段内容。
